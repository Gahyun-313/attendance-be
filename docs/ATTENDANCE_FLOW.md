# 📲 NFC Attendance Flow

## 🔄 처리 흐름

```text
학생 로그인
  ↓
Android에서 NFC UID 인식
  ↓
JWT와 UID를 포함해 체크인 요청
  ↓
사용자·조직·태그·활성 세션 검증
  ↓
사용자+세션 단위 Redisson Lock 획득
  ↓
기존 기록 확인 및 출석 가능 시간 검증
  ↓
PRESENT 또는 LATE 결정·저장
  ↓
트랜잭션 커밋
  ├─ 앱에 결과 반환
  └─ 관리자 WebSocket 이벤트 발행
```

## ✅ 서버가 검증하는 항목

1. JWT가 유효하며 학생 권한인지 확인합니다.
2. 전달된 UID에 해당하는 NFC 태그가 활성 상태인지 확인합니다.
3. 태그와 연결된 활성 출석 세션을 찾습니다.
4. 현재 시간이 출석 가능한 범위인지 확인합니다.
5. 동일 사용자·세션의 기존 출석 기록을 확인합니다.
6. 세션 정책에 따라 `PRESENT` 또는 `LATE`를 계산합니다.
7. 저장 완료 후 관련 캐시를 무효화합니다.

최종 출석 상태는 서버에서 결정합니다. 따라서 변조된 클라이언트가 상태나 사용자 ID를 임의로 전송해도 그대로 신뢰하지 않습니다.

## 🔒 동시성 경계

분산 락 키는 사용자와 세션 조합을 기준으로 만듭니다. 서로 다른 학생의 출석은 병렬로 처리하면서 동일 학생의 동일 세션 요청만 직렬화하기 위한 선택입니다.

락은 레코드 조회와 저장을 보호하고 트랜잭션이 실제로 종료된 뒤 해제합니다. `READ_COMMITTED`를 사용해 다음 요청이 직전 요청의 커밋 결과를 볼 수 있도록 했습니다.

## 📤 응답 원칙

- 최초 정상 요청: 출석 기록 생성 또는 상태 갱신
- 이미 처리된 출석: 의도한 409 Conflict
- 락 획득 실패: 409 Conflict
- 유효하지 않은 태그·세션·시간: 도메인 오류 코드로 응답
- 예상하지 못한 오류: 공통 예외 응답 형식 사용

동시 요청을 모두 성공시키는 것이 아니라, 최초 요청만 처리하고 나머지를 예측 가능한 비즈니스 오류로 반환하는 것을 목표로 했습니다.
